## 18:00 · DSA A1 — what things actually cost

### Cover

- String concatenation in a loop.
- `collections`, properly.
- 1–2 problems.

### Gist
A CPython `list` is a contiguous array **of pointers**, plus spare capacity at
the end. So: index O(1), append amortized O(1), and `pop(0)` / `insert(0, x)`
are O(n) because every remaining pointer shifts down one slot. There is no
cheap front. `collections.deque` is a doubly-linked list of fixed-size blocks
(64 pointers each) — O(1) at both ends, but indexing the middle is O(n). Pick
by which end you touch.

`tuple` is immutable and fixed-size: no spare capacity, smaller footprint, and
hashable if its contents are — so it can be a dict key or set member. Use it
for a fixed record, use a list for a growing sequence.

`s += x` in a loop is the classic trap: strings are immutable, so each `+=`
allocates a new string and copies everything — O(n^2) over the loop. CPython
has an in-place realloc optimisation when the refcount is 1, which sometimes
hides this and never guarantees it. Use `"".join(parts)`, which walks once to
size the buffer and once to fill it.

**`collections` worth knowing cold:** `deque` (also `maxlen`, `rotate`),
`Counter` (`most_common`, and it does multiset arithmetic), `defaultdict`
(no `setdefault` dances), `namedtuple` / `dataclass` for records.

3. Verify each against `np.linalg` afterward.

### Gist — all three fall out of one elimination pass
Row-reduce `A` to upper triangular with partial pivoting, tracking row swaps.
From the result:

- **Determinant** = product of the pivots, times `-1` per row swap.
  Elimination (adding a multiple of one row to another) does not change `det`;
  swapping two rows flips its sign; scaling a row scales it.
- **Rank** = the number of non-zero pivots — but "non-zero" needs a
  **tolerance**, not `== 0`. Floating point turns exact zeros into `1e-17`.
  Something like `tol = max(shape) * eps * largest_pivot`. This is the lesson
  of the session: rank is numerically fragile, and the honest tool is the SVD
  (count singular values above a tolerance), which is what
  `np.linalg.matrix_rank` actually does.
- **Inverse** = carry on to reduced row echelon form on `[A | I]`, same as
  Tuesday but vectorized — a whole row operation is one broadcast subtraction
  now, not a loop.

Check with `np.allclose` against `np.linalg.det` / `matrix_rank` / `inv`. When
something disagrees in the 12th decimal, that is not a bug, that is floating
point. Then try an ill-conditioned matrix (a Hilbert matrix, `1/(i+j+1)`) and
watch the gap blow open — that is the preview of why "just invert it" is bad
advice in real ML code, and why you will use `solve` instead later.
