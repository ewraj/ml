### Gist
`itertools` is the "I was about to write a nested loop" library. The ones that
actually come up: `accumulate` (running totals — prefix sums for free),
`combinations` / `permutations` / `product` (brute force written honestly),
`groupby` (**only groups adjacent items — sort first**, this is the standard
gotcha), `chain`, `zip_longest`, `pairwise` (sliding window of 2). They are
lazy: they generate on demand, so memory stays O(1) even over a huge range.

`functools.lru_cache` / `cache` turns exponential recursion into linear by
memoising on the argument tuple. Two conditions to remember: the arguments must
be **hashable** (no lists — pass tuples), and the function must be **pure**
(same args, same answer, no side effects). This is top-down DP in one decorator
line, and in an interview it is worth saying out loud that you know what it is
doing rather than leaning on it silently. Also `functools.reduce`, and
`cmp_to_key` when a comparator is genuinely easier than a key.

## 19:00 · ML W1 — Why numpy is fast

This is a C mental model, and the session where your systems background is a
straight advantage. The claim to destroy tonight: "numpy is fast because it is
written in C." True and useless. **Why** does C help here?

### Cover
- Strides, views vs copies, memory layout.
- Why broadcasting allocates nothing.
- Benchmark Tuesday's pure-Python `matmul` against numpy's. Explain the gap
  **in writing**.

### Gist — where the 100x actually comes from
Four separate costs, and it is worth knowing which one dominates:

1. **Boxing.** A Python `list` of floats is an array of pointers to individual
   `PyFloatObject`s — each one a heap allocation with a refcount and a type
   pointer, scattered across memory. A numpy array is one flat block of raw
   `float64`. No pointer chase, no unboxing, and the CPU prefetcher can
   actually work.
2. **Interpreter overhead per element.** `a[i] + b[i]` in a loop costs bytecode
   dispatch, two `__getitem__` calls, type dispatch on `+`, and a new object
   allocation — hundreds of ns for one addition. In numpy that inner loop is a
   compiled C loop over contiguous memory: sub-ns per element.
3. **SIMD and cache.** Contiguous `float64` means the vector units can do 4–8
   lanes per instruction, and a cache line carries 8 useful values instead of 8
   pointers to elsewhere.
4. **BLAS.** `A @ B` does not run numpy's own loop at all — it calls into a
   tuned BLAS (OpenBLAS/MKL), which is cache-blocked, hand-vectorised, and
   multi-threaded. That is why `matmul` specifically is more like 1000x than
   100x, and why your benchmark gap is *bigger* than the gap for `vector_add`.
   Check `np.show_config()` to see what you are actually linked against.

### Strides — the mechanism
An ndarray is a pointer + `shape` + `strides` + `dtype`. `strides[k]` is how
many **bytes** to step to move one along axis `k`. Everything follows:

- **Transpose is free.** `A.T` swaps shape and strides and returns a *view* —
  no data moves. Same for basic slicing, `reshape` when it can be done without
  copying, and `x[::2]` (stride doubles).
- **Broadcasting allocates nothing** because a stretched axis is given
  **stride 0**: step zero bytes, read the same value again. `(n,1)` against
  `(1,m)` is two stride-0 tricks, not two materialised `(n,m)` arrays.
- **Fancy indexing copies.** `x[[0,2,5]]` and boolean masks cannot be expressed
  as a stride pattern, so they allocate. Basic slice = view, fancy index = copy.
  Check with `x.base is not None`, and `x.flags` for `C_CONTIGUOUS` /
  `OWNDATA`.
- **Views alias.** Writing through a view writes the original. That is a
  feature and it is also the source of a whole genre of silent bugs.
- **C order vs F order** decides which axis is contiguous, so summing along the
  contiguous axis is measurably faster than along the strided one. Measure it.

### The benchmark
Use `timeit` or `perf_counter` with a warm-up, several repeats, take the min,
not the mean. Sweep n = 32, 64, 128, 256 and plot or tabulate. Watch the ratio
*grow* with n — that is cache blocking, not a constant factor.
